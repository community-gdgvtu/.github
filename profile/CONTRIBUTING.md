# Contributing to GDG VTU

Thanks for wanting to contribute to **GDG on Campus VTU Belagavi**! This guide covers contributions to this organization profile repo and general practice across our project repos.

## Ways to Contribute

- **Code** — features, bug fixes, or improvements on any GDG VTU project repository.
- **Content** — workshop material, study jam guides, event write-ups, or documentation.
- **Design** — posters, banners, or UI/UX for community projects and events.
- **Community** — helping run events, mentoring at hackathons, or triaging issues.

## Getting Started

```bash
# 1. Fork the repository you want to contribute to
# 2. Clone your fork
git clone https://github.com/<your-username>/<repo-name>.git
cd <repo-name>

# 3. Create a feature branch
git checkout -b feature/your-feature-name

# 4. Make your changes and commit
git add .
git commit -m "feat: describe your change"

# 5. Push and open a Pull Request
git push origin feature/your-feature-name
```

## Pull Request Guidelines

- Keep PRs focused on a single change or feature.
- Write a clear PR description: what changed and why.
- Link any related issue.
- Ensure the project builds/runs locally before requesting review.
- Be responsive to review comments — small back-and-forth is normal.

## Commit Message Style

Use short, present-tense messages, optionally with a type prefix:
```
feat: add dark mode toggle
fix: resolve firebase auth redirect bug
docs: update setup instructions
```

## Issues

- Search existing issues before opening a new one.
- Use clear titles and include steps to reproduce for bugs.
- Tag issues appropriately (`bug`, `enhancement`, `docs`, `good first issue`) where labels exist.

## Code Style

- Match the existing formatting/linting configuration of the repo you're working in.
- Comment non-obvious logic.
- Do not commit secrets, API keys, or `.env` files.

## Code of Conduct

All contributors are expected to follow our [Code of Conduct](./CODE_OF_CONDUCT.md).

## Questions

Reach out to the current organizing team (see the **Organizers** section in the [README](./README.md)) or open a discussion/issue.
